# 카메라 스캐닝

> [marcinz606/NegPy](https://github.com/marcinz606/NegPy) `docs/CAMERA_SCANNING.md`(0.59.0 기준)의 한글 번역입니다. 원문과 다를 경우 원문이 우선합니다.

**카메라 스캐닝(Camera Scanning)** 탭은 테더링된 카메라로 네거티브를 촬영해 NegPy에 바로 가져옵니다. 별도의 촬영 앱도, 폴더를 옮기는 작업도 필요 없습니다. 두 가지 모드가 있고, 연결된 하드웨어에 따라 자동으로 선택됩니다.

---

## 하는 일

**일반 카메라 스캐닝.** 사용 중인 조명 아래서 프레임을 한 번 노출해, 보통의 RAW 파일처럼 가져와서 다른 파일과 똑같이 처리합니다. 지원되는 카메라만 있으면 됩니다.

**협대역(Narrowband) RGB 스캐닝.** RGB [Scanlight](https://github.com/jackw01/scanlight)를 연결하면 조명이 빨강 → 초록 → 파랑 순서로 점등되고, 카메라는 채널마다 한 번씩 노출합니다. NegPy의 **Trichrome Scan** 병합 기능이 이 세 장의 RAW를 서브픽셀 단위로 정렬해 반전 전에 한 프레임으로 합칩니다.

한 번보다 세 번 찍는 게 더 나은 이유는, 광대역(broadband) 노출 한 번으로 찍으면 각 염료 층이 인접 채널을 오염시키기 때문입니다. 세 채널 중 초록 베이어 필터가 가장 넓어서, 빨강과 파랑 빛의 누출을 동시에 받아들입니다. 한 번에 좁은 대역 하나씩만 쓰면 이 크로스토크가 구조적으로 제거되고, 각 채널이 센서의 전체 다이나믹 레인지를 나눠 쓰지 않고 온전히 가져갑니다.

---

## 필요한 것

| | |
|---|---|
| **카메라** | 라이브뷰와 원격 촬영을 지원하며 [libgphoto2가 구동할 수 있는](http://gphoto.org/proj/libgphoto2/support.php) 바디라면 무엇이든. 목록에 없는 바디도 범용 PTP 드라이버로 동작하는 경우가 많습니다. a7C II는 동작 확인됨. |
| **python-gphoto2** | 선택적 의존성, 자유 소프트웨어(LGPL). `pip install gphoto2`. |
| **Scanlight** *(선택)* | 협대역 RGB 스캐닝에만 필요. 일반 카메라 스캐닝은 이것 없이도 동작. |

**이 중 아무것도 없어도 NegPy는 잘 동작합니다.** python-gphoto2가 없으면 카메라 스캐닝 탭에 한 줄짜리 설치 안내가 표시될 뿐, NegPy의 다른 부분은 전혀 영향받지 않습니다. 독점(proprietary) 요소는 전혀 없습니다 — libgphoto2는 LGPL이고, 벤더 SDK는 번들되거나 링크되거나 요구되지 않습니다.

> ⚠️ **macOS와 Linux 전용입니다.** libgphoto2는 Windows 빌드가 없어서 Windows용 wheel도 없고, 이 탭은 Windows에서 연결할 수 없습니다.

---

## 설정

```bash
uv sync --group camera     # 또는: pip install gphoto2
```

설치는 이게 전부입니다. libgphoto2는 wheel 안에 포함되어 있어서 따로 다운로드하거나 빌드하거나 어딘가에 넣을 필요가 없습니다. 앱을 직접 패키징한다면 `make build` 전에 같은 명령을 실행하세요. 그러면 빌드에 libgphoto2의 카메라 드라이버가 함께 번들됩니다. 이 단계를 건너뛰면 패키징된 앱에는 설치 안내만 표시됩니다.

그다음 카메라를 **PC Remote** 모드로 설정하고 USB로 연결하세요. NegPy가 자동으로 감지합니다. 주소를 입력할 필요도, 로그인도, 페어링도 없습니다.

> macOS에서는 PTP 카메라를 다른 무언가가 붙잡고 있지 않은 순간 시스템 카메라 데몬이 즉시 차지해버리고, 몇 분 동안은 놓아주지 않습니다. 그래서 NegPy는 카메라 스캐닝 패널이 바디를 인식하는 순간 바로 그 권한을 가져와 유지합니다 — 이 패널이 열려 있는 동안 카메라는 NegPy 소유이며, Preview, Photos, Image Capture 등 다른 테더링 소프트웨어는 사용할 수 없습니다. 케이블을 뽑으면 다시 돌려줍니다.
>
> 이 데몬을 깨우는 건 카메라를 찾는 어떤 애플리케이션이든 해당되며, 사용자가 직접 연 앱일 필요는 없습니다. 백그라운드 동기화 클라이언트가 흔한 원인으로, 조용히 반복적으로 이 짓을 합니다 — 눈에 보이는 실행 중인 프로그램이 없는데도 카메라가 사용 중으로 뜬다면 먼저 이런 것들을 확인하세요.

## 스캔하기

**프레이밍과 포커스.** **Live View & Scan**을 엽니다. 이미지의 아무 곳이나 클릭하면 카메라의 *하드웨어* 포커스 확대 기능이 그 지점을 겨냥합니다. 다시 클릭하면 전체 프레임으로 돌아옵니다. 백색광 및 일반(카메라 단독) 스캐닝에서는 툴바에서 ISO, 셔터, 조리개를 실시간으로 설정할 수 있습니다. 보정된 RGB 프리셋을 사용 중일 때는 이 컨트롤들이 숨겨지고 프리셋 값에 고정되어(아래 **프리셋** 참고) 스캔 값이 흔들리지 않습니다. 바디가 지원하지 않는 컨트롤은 비활성화(회색) 표시됩니다. 전자식 조리개가 없는 렌즈에서 조리개가 흔히 이렇게 되는데, 대부분의 인라징(enlarging)/매크로 렌즈가 여기 해당합니다.

**보정 (RGB 모드).** 스캔에 쓸 ISO와 조리개를 설정하세요. 프리셋 드롭다운 옆의 **+**를 누르고, 작은 사각형을 투명한 필름 베이스 위에 놓은 뒤, 프리셋 이름을 붙이고 실행합니다. 프레임 사이의 리베이트(rebate) 스트립이 이상적인 타깃입니다. 보정은 그 패치를 측광해 공용 셔터 값 하나와 채널별 LED 레벨을 계산하며, 그 결과 각 채널이 클리핑 직전까지 도달합니다. ISO와 조리개 값도 함께 기록됩니다.

이 하이라이트가 중요한 이유는, 반전 후 이 투명 베이스가 *블랙 포인트*가 되기 때문입니다. 그래서 클립 가드가 raw 베이어 포토사이트를 확인해 어느 채널이라도 포화되면 노출을 낮춥니다. 필름 재고(stock)마다 프리셋을 한 번씩 저장해두고 재사용하세요.

현재 노출로 타깃에 도달할 수 없으면 프로브 단계에서 실행이 멈춥니다. 팝업이 어느 방향으로 조정할지 알려줍니다 — 과다노출이면 조리개를 조이거나 ISO를 낮추고, 부족노출이면 조리개를 열거나 ISO를 올리라는 식입니다. **이 경우 프리셋은 저장되지 않습니다.** 열려 있는 창에서 값을 조정하고 다시 보정하세요.

**프리셋.** 선택한 프리셋은 RGB 레벨, ISO, 셔터, 조리개와 함께 읽기 전용으로 표시됩니다. 스캔은 매 프레임 전에 그 노출값을 바디에 강제로 적용하므로, 다이얼이 실수로 돌아가도 결과가 틀어지지 않습니다. 대신 직접 프리셋을 만들려면 드롭다운에서 **Create a manual preset…**를 선택하세요. 슬라이더와 노출 스테퍼가 잠금 해제됩니다. 값을 맞춘 뒤 저장(플로피 디스크) 버튼을 눌러 이름을 붙이고 저장합니다. White는 백색광 프리셋의 채널 전용인데, Scanlight가 RGB와 White를 동시에 켤 수 없기 때문입니다.

**스캔.** 출력 폴더와 프리셋을 고른 뒤, 프레임마다 **Scan**을 누릅니다. 파일은 롤별 하위 폴더에 자동 번호가 매겨져 저장되고, 자동으로 임포트·병합되어 셔터를 누른 직후 반전된 포지티브가 나타납니다. **Retake**는 카운터를 올리지 않고 현재 프레임을 다시 찍습니다. **Delay between exposures** 설정은 적/녹/청 촬영 사이에 지연을 추가해서, 오래된 바디가 이전 촬영분을 다 내보내기 전에 새 촬영 명령이 도착하는 것을 막아줍니다 — 일부 카메라는 촬영 명령이 너무 빨리 연달아 들어오면 USB/PTP가 멈춰버리는데, 이를 방지하기 위한 설정입니다.

**협대역 스캔.** 협대역 RGB LED로 조명한 스캔은 백색광 스캔보다 채도가 높게 나오는데, 각 채널이 염료의 흡수 피크 근처만 샘플링하고 광대역 조명에서 자연스럽게 생기는 스펙트럼 겹침이 없기 때문입니다. Process 패널의 **Linear RAW** 옆에 있는 **Narrowband** 토글이 번들된 RGBScan 입력 프로파일로 이를 보정하며, 프리뷰와 모든 익스포트에 적용됩니다. Export 설정에서 **Input ICC**를 명시적으로 지정하면 이 설정이 우선합니다.

### 센서 보정

협대역 RGB 광원으로 한 번만 촬영한 스캔은 어떤 슬라이더로도 고쳐지지 않는 색조로 나올 수 있습니다. 노랑이 주황 쪽으로 틀어지는 게 전형적인 신호입니다. 원인은 **센서 크로스토크**입니다 — 카메라의 색 필터 통과대역이 광원의 대역과 겹치기 때문에, 초록 픽셀이 파랑 LED와 빨강 일부를 함께 받아들이고, 모든 채널이 이웃 채널의 성분을 조금씩 섞어 담게 됩니다. 이는 필름과 무관하게 사용 중인 센서와 광원 조합의 고정된 특성입니다.

이를 보정하려면 필름 홀더를 비운 채로 빛만 세 번 촬영하세요 — 빨강만, 초록만, 파랑만. 스캔할 때와 같은 설정으로, 클리핑 바로 아래까지 노출합니다. 그다음 **Calibration** 패널을 열어 *Single-Shot Narrowband Calibration*을 찾고, 보정 버튼을 눌러 세 장의 촬영본을 선택한 뒤 프로파일 이름을 붙여 저장합니다. 선택한 프로파일은 반전 전, 선형(linear) 영역에서 3×3 행렬로 모든 스캔의 색을 다시 분리해줍니다. 프로파일은 `NegPy/sensor` 폴더에 TOML 파일로 저장됩니다. 프로파일을 바꾼 뒤에는 **Batch Analysis**를 다시 실행하세요.

RGB 3연속(trichrome) 스캔에는 이 보정을 쓰지 마세요. 이런 스캔은 구조적으로 크로스토크가 없는데, 각 채널이 자기만의 단일 광원 노출에서 나오기 때문이며, NegPy는 3연속 소스에 대해 이 보정을 자동으로 건너뜁니다. 전용 필름 스캐너 역시 센서 크로스토크가 없습니다 — Coolscan의 단색(mono) CCD는 한 번에 LED 하나씩만 읽습니다. 이런 스캐너에 남는 색 오차는 필름 염료 크로스토크이며, 밀도 영역의 **Crosstalk** 행렬이 이를 처리합니다([CROSSTALK.md](CROSSTALK.md) 참고).

## 문제 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 카메라 표시등이 **"사용 중(in use)"**(주황색 힌트) | 다른 프로그램이 바디를 점유 중이고, PTP 카메라는 한 번에 한 프로그램만 잡을 수 있습니다. macOS에서는 시스템 카메라 데몬이 점유하는 것이 보통이며, 카메라를 찾는 어떤 애플리케이션이든 이를 깨울 수 있습니다. 흔히 창도 알림도 없는 **백그라운드 동기화 클라이언트**가 원인입니다 — 로그인 항목으로 실행 중인 Google Drive가 이런 문제를 일으키는 것이 확인되었고, Dropbox 등 비슷한 도구들도 마찬가지입니다. | 해당 백그라운드 앱을 종료하거나, 자동 실행된다면 **시스템 설정 → 일반 → 로그인 항목**에서 제거하세요. 케이블을 뽑았다 다시 꽂아도 카메라가 풀리지만, 그 앱이 다시 요청할 때까지만입니다. Preview, Photos, Image Capture가 실제로 열려 있을 때도 같은 문제를 일으킵니다. 카메라가 풀리면 NegPy가 알아서 재연결합니다. |
| 카메라를 못 찾고, 다른 프로그램도 실행 중이 아님 | 바디가 PC Remote 모드가 아니거나, 대용량 저장소(mass-storage)/MTP로 연결됨. | 카메라의 USB 연결 모드를 **PC Remote**로 설정하세요. |
| `[-10] Timeout reading from or writing to the port`가 뜨고 다른 프로그램도 점유 중이 아님 | 연결 중이던 프로그램이 죽은 경우. *카메라* 쪽은 세션이 여전히 열려 있다고 판단해 새 세션을 거부합니다. 저절로 풀리는 타임아웃은 조용히 재시도돼서 사용자 눈에 띄지 않으므로, 이 메시지가 보인다는 건 저절로 풀리지 않았다는 뜻입니다. | 카메라 전원을 껐다 켜거나, 케이블을 뽑았다 다시 꽂으세요. 컴퓨터 쪽에서 고칠 방법은 없습니다. |
| 라이브뷰가 검게 나옴 | 바디가 PC Remote 모드에서 빠졌거나 렌즈 캡이 씌워져 있음. | 카메라 전원을 껐다 켜세요. |
| 스캔 창이 프리뷰 대신 **"no live view"**로 열림 | libgphoto2의 해당 바디 항목에 프리뷰 기능이 없음. 바디가 실제로 이 기능을 지원하지 않거나(Sony a6000), MTP 모드로 연결되어 있어서(이 모드에서는 어떤 바디도 지원 안 됨). | 메시지에 MTP가 언급되어 있다면 카메라 USB 모드를 **PC Remote**로 바꾸고 재연결하세요. 그렇지 않다면 정상적인 동작입니다 — 스캔은 정상적으로 되지만, 프레이밍과 포커스는 카메라에서 직접 맞춰야 하고, 보정은 라이브뷰를 통해 조준하는 기능이라 사용할 수 없습니다. |
| 촬영 결과가 RAW 대신 JPEG로 나왔다는 메시지 | 카메라의 화질 설정이 JPEG이거나, RAW+JPEG 설정에서 처리된 파일이 선택됨. | 화질 설정을 **RAW only**로 바꾸고 다시 시도하세요. |
| 조리개 스테퍼가 비활성화(회색) 표시됨 | 렌즈에 전자식 조리개가 없음. | 정상입니다. 조리개는 렌즈에서 직접 설정하세요. |
| 설정값이 이전 값으로 되돌아감 | 속성 쓰기가 비동기적이라 바디가 반영할 시간이 필요함. | NegPy는 값이 반영될 때까지 폴링하고, 끝내 반영되지 않으면 경고를 남깁니다. 계속 안 된다면 바디의 현재 모드에서 그 설정을 쓸 수 없는 것입니다. **M** 모드로 시도해보세요. |
| Scanlight가 감지되지 않음 | 잘못된 USB-C 포트 사용. | Scanlight에는 포트가 두 개 있고 데이터 전송은 한쪽에서만 됩니다. 나머지 하나는 전원 전용입니다. 데이터 포트를 사용하세요. |

## 참고 및 제약사항

- **USB 전용입니다.** libgphoto2는 일부 카메라를 네트워크로도 제어할 수 있지만 Sony 바디는 해당되지 않습니다. 이 탭은 USB 테더링 워크플로입니다.
- **테스트는 Sony 바디로만 되어 있습니다** — 현재 보유한 하드웨어가 그것이기 때문입니다. NegPy는 특정 제조사를 가정하지 않고 모든 컨트롤을 조회해서 사용합니다. `iso`와 `shutterspeed`는 어디서나 이름이 같습니다. 조리개는 Sony·Panasonic에서는 `f-number`, Canon·Nikon·Fujifilm·Olympus·Sigma에서는 `aperture`입니다. RAW 확장자는 카메라가 결정하며, 스틸 이미지는 카드가 아니라 메모리로 바로 전송됩니다. Canon과 Nikon은 기본적으로 카드에 저장하도록 되어 있어 카드 없이는 촬영이 안 됩니다. 다른 브랜드 사용 경험 제보는 언제나 환영입니다.
- **포커스 확대 기능은 제조사마다 다릅니다.** Sony는 줌 배율과 타깃 지점을 속성 하나에 함께 담아서, 클릭 한 번으로 확대와 조준이 동시에 됩니다. Canon(`eoszoom`)과 Nikon(`liveviewimagezoomratio`)은 이를 분리해서 제공하며, 좌표 체계가 알려져 있지 않아 클릭하면 바디가 이미 보고 있던 지점이 확대됩니다. 그 외 모든 바디는 이 기능 자체가 없어서 자동으로 비활성화됩니다.
- **macOS에서 테스트되었습니다.** Python은 이식성이 있고 libgphoto2는 Linux 우선 프로젝트라 Linux에서도 최소한 동등하게 동작할 것으로 예상되지만, 검증되지는 않았습니다.
- **속도.** a7C II로 USB 연결 시 RGB 3연속 촬영에 약 6초가 걸립니다. 이 시간의 거의 전부는 파일 크기가 아니라 바디의 이미지 전송 지연입니다. 스틸 촬영은 실행 중인 라이브뷰 세션 내부에서 이뤄지므로 프레임마다 재연결하지 않습니다.
- **크레딧.** R/G/B 순차 촬영과 노출 보정 방식은 [rohanpandula/TriRGB](https://github.com/rohanpandula/TriRGB)에서 가져왔습니다. 조명 장치는 [jackw01/scanlight](https://github.com/jackw01/scanlight)입니다. 카메라 제어는 [python-gphoto2](https://github.com/jim-easterbrook/python-gphoto2)를 통해 이뤄집니다. 협대역 방식은 Flückiger 등의 삼색(trichromatic) 필름 스캐닝 연구를 따릅니다.
